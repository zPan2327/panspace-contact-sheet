# 写 demo 的规范

这个仓库只放 UI 骨架，不放业务内容，所以给组件写 demo 时目标也只有一个：展示组件本身（props、动画、交互），而不是展示某个业务场景。

## demo 应该展示什么

- props 的效果：Sheet 的 isOpen / onClose / ariaLabel / children；Button 的 variant / size / href / onClick
- 动画过程：打开（遮罩毛玻璃渐显、面板弹性上浮并居中、内容行逐行淡入）与关闭（内容行反向错开退场）
- 交互契约：点遮罩关闭、面板内点击不冒泡、Esc 关闭、打开时锁定页面滚动

## 不要做什么

- 不要编造业务内容：真实公司名、真实邮箱、真实用户数据、真实订单号
- 不要把占位文案写成看起来像内容结构的固定套路（例如固定的「项目介绍 / 技术实现 / 技术亮点 / 应用价值」四段式），那会让人以为弹窗必须长这样
- 不要引用外部图片或外部截图链接
- 不要在 demo 里引入仓库里没有声明的依赖

## 占位文案约定

统一用下面这几个，保持全仓库一致：

| 位置 | 文案 |
| --- | --- |
| 标题 | 此处是标题 |
| 正文 | 此处是文本 |
| 按钮 | 按钮 / 按下 |
| 辅助说明 | 此处是辅助说明文本 |
| 图标位 | 中性色块占位，注释标明此处放图标 |

## 想再加一行

在弹窗内容层里直接加一个 div 并带上 `sheet-detail-row` 即可，进场延迟由 `:nth-child(1..8)` 自动递增，不需要写 JS。注意它必须是内容层的直接子元素，中间多包一层就会退化成同时出现。

## 截图与录屏

如果要放进仓库，请自己截或自己录，并在 README 里注明是哪次改动截的。不要引用外部链接，也不要放没有出处的图 —— 目前 README 的效果预览只有文字描述，正是出于这个原因。

## 检查清单

- 组件能独立渲染，不依赖 demo 之外的业务数据
- 打开与关闭两条动画路径都看得到
- 遮罩点击、Esc、面板内点击三种交互都体现出来
- 文案全部来自上面的约定
- 暗色模式看一眼（在 html 标签上加 class 即可）
